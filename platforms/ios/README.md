# iOS 接入计划（未实现）

这里是规划边界，不是可编译 iOS 工程，也没有承诺 App Store、TestFlight 或现成第三方宿主兼容性。

可以复用：`ginput/rime/` 的输入规则、Lua 纠错/排序、TSV 词库格式、`tests/fixtures/dictionary-v1.json`。前提是未来宿主确实包含兼容 librime/librime-lua；必须实测，不能把 Mac 配置包直接称作 iOS 版本。

如果做自有键盘，需要新增：

- Swift 容器 App 和 Keyboard Extension，键盘布局、候选交互、输入代理适配。
- 选定并审核 librime/Lua 嵌入方案、上游许可证、设备架构、内存和启动延迟。
- 独立的沙盒目录/资源打包；若需要容器与扩展共享数据，设计 App Group 和相应权限。
- 把 TSV 导入器实现为 Swift 并运行同一格式契约；Python CLI 不嵌进扩展。
- 明确密码框、禁止第三方键盘的应用、系统切换键盘等系统边界。
- 自定义键盘权限、隐私说明、签名与设备分发方案。不能套用本次 Mac 配置无需开发者帐号的结论。

先离线完成：拼音输入 → 候选 → 上屏、删除、空格/标点、切换键盘、个人词条导入与重启保留。再测试内存压力、扩展终止与恢复、敏感输入边界和重复导入。任何网络权限或跨设备同步另行设计和授权；本次不搭建同步服务。
